# 06 — Database (Firebase Firestore)

**Status: [VERIFIED]**

---

## Database Engine

**Firebase Firestore** (NoSQL document database)
- Accessed entirely client-side via the Firebase JavaScript SDK v12
- No server-side database access
- Security enforced exclusively through `firestore.rules`

---

## Collections

### `inquiries` — Project Inquiry Submissions

**Purpose:** Stores project inquiry form submissions from potential clients.

| Field | Type | Required | Constraints |
|---|---|---|---|
| `name` | string | YES | 1–100 chars |
| `email` | string | YES | 3–150 chars, lowercase |
| `company` | string | NO | max 100 chars |
| `projectType` | string | YES | 1–100 chars |
| `budgetRange` | string | NO | max 50 chars (defaults to 'Flexible') |
| `timeline` | string | YES | 1–50 chars |
| `description` | string | NO | max 5000 chars |
| `selectedTech` | array | NO | max 20 items |
| `referenceNumber` | string | YES | Format: `DCP-YYYY-NNNN` (e.g., `DCP-2026-8942`) |
| `status` | string | YES | `'pending' \| 'reviewed' \| 'contacted'` |
| `authUid` | string | NO | Firebase Auth UID or `'guest'` |
| `submittedAt` | string | YES | ISO 8601 timestamp string |
| `createdAt` | Timestamp | YES | Firestore server timestamp |

**Document path:** `/inquiries/{inquiryId}` (auto-ID)

**Write rules:** Public create allowed. Schema validated in Firestore rules.

**Read rules:** Authenticated users can read their own docs (`resource.data.authUid == request.auth.uid`)

**Update/Delete:** Blocked (`allow update, delete: if false`)

**Generated by:** `submitProjectInquiry()` in `src/lib/firebase.ts`

### `newsletter_subscribers` — Email Subscriptions

**Purpose:** Stores email addresses of newsletter subscribers.

| Field | Type | Required | Constraints |
|---|---|---|---|
| `email` | string | YES | 5–150 chars, lowercase, valid email regex |
| `source` | string | NO | max 50 chars (e.g., `'newsletter_component'`) |
| `status` | string | YES | `'active' \| 'unsubscribed'` |
| `subscribedAt` | string | YES | ISO 8601 timestamp string |
| `createdAt` | Timestamp | YES | Firestore server timestamp |

**Document path:** `/newsletter_subscribers/{subscriberId}` (auto-ID)

**Write rules:** Public create allowed. Schema validated.

**Read/Update/Delete:** Blocked for all (PII protection)

**Generated by:** `subscribeToNewsletter()` in `src/lib/firebase.ts`

## Security Rules Summary

**File:** `firestore.rules`

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // inquiries: 
    //   CREATE: public (with schema validation)
    //   GET/LIST: authenticated, own docs only
    //   UPDATE/DELETE: blocked
    
    // newsletter_subscribers:
    //   CREATE: public (with schema validation)
    //   READ/UPDATE/DELETE: blocked
  }
}
```

Key validations in rules:
- Required fields existence check (`hasAll`)
- Allowed fields only (`hasOnly`) — prevents injection of extra fields
- String length bounds on every field
- Status enum enforcement
- No server-side deduplication for newsletter emails (TECHNICAL DEBT TD-002)

## Authentication

**Method:** Firebase Anonymous Authentication

**Flow:**
1. `ensureAuth()` in `firebase.ts` checks `onAuthStateChanged`
2. If no user → `signInAnonymously(auth)` → creates anonymous session
3. `auth.currentUser.uid` is stored in inquiry docs as `authUid`
4. If anonymous auth fails → falls back to `authUid: 'guest'` (write still attempted)

**Purpose:** Required to satisfy Firestore security rules for read access to own inquiries. Newsletter subscription does NOT require auth (create is publicly allowed).

## Firebase Initialization

**Config file:** `firebase-applet-config.json` (contains real API keys — committed to repo)

**Initialization pattern:**
```typescript
const app = getApps().length === 0 ? initializeApp(firebaseConfig) : getApp();
export const db: Firestore = firestoreConfig.firestoreDatabaseId
  ? getFirestore(app, firestoreDatabaseId)
  : getFirestore(app);
export const auth: Auth = getAuth(app);
```

Supports custom Firestore database ID via `firestoreDatabaseId` field in config.

## Error Handling

**`handleFirestoreError(error, operationType, path)`** — Enriches errors with auth context info (UID, email, isAnonymous, providerData), logs to console, and re-throws as JSON-stringified Error for upstream catching.

**`OperationType` enum:** `CREATE | UPDATE | DELETE | LIST | GET | WRITE`

## Data Flow: Inquiry Submission

```
User fills ProjectInquiryBuilder form
  → setFormData() (local state)
  → Submit button clicked
  → setIsSubmitting(true)
  → ensureAuth() — get/create anonymous Firebase user
  → Generate referenceNumber (DCP-YYYY-NNNN)
  → addDoc(collection(db, 'inquiries'), payload)
  → Firestore rules validate payload
  → Document created
  → { id, referenceNumber } returned
  → confetti() + soundEngine.playSuccessChime()
  → setSubmitted(true) — show success state with referenceNumber
```

```
  → ensureAuth()
  → addDoc(collection(db, 'newsletter_subscribers'), payload)
  → Firestore rules validate payload
  → Document created
  → Success state shown
```

## Known Limitations (Resolved in Target Laravel Migration)

1. **No duplicate email prevention** — Newsletter can receive duplicate subscriptions for same email address in Firestore. *Resolved in Laravel via database unique constraint on `email`.*
2. **No admin dashboard** — No Firebase console UI or custom admin interface for viewing inquiries. *Resolved in Laravel via dedicated React Admin CMS (`/admin`).*
3. **Anonymous auth persistence** — Anonymous sessions are browser-scoped; users cannot retrieve their inquiry across devices. *Resolved in Laravel via session-based CSRF and administrative lead management.*

## Target Database Migration: Relational Schema (MySQL / PostgreSQL)

Under **ADR-007**, Firebase Firestore will be completely retired in favor of a relational schema managed via Laravel migrations and Eloquent models:
- `users`: Admin authentication with role management.
- `inquiries`: Lead submissions with internal notes, status pipeline, and admin management.
- `newsletter_subscribers`: Deduplicated subscriber list with unique email constraint and cryptographic unsubscribe tokens.
- `projects`, `capabilities`, `faqs`, `site_settings`: Dynamic CMS content.
